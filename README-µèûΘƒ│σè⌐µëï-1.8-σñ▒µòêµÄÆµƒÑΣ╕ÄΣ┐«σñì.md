# 抖音助手 1.8 · 1.7 功能无效问题排查

目标版本：抖音 40.8.0，Theos / Logos 源码。以下是源码级更改，**没有编译或真机测试通过的结论**。

## 修复变更

1. **默认 Hook 组未显式初始化**：`DYYY.xm` 中有自定义 `%ctor`，本次添加 `%init;`；`AutoPlay` Hook 从用户协议启动判断分支中移出。运行时通过独立开关控制实际功能。
2. **两个插件设置入口使用不同 UI**：双指长按打开旧的 `DYYYSettingViewController`，已改为打开与菜单一致的 `DYYYSystemSettingsViewController`。设置页顶部有「已加载插件版本 1.8」便于检查插件是否真的更新。搜索框在同一页面。
3. **长按需拉出、原生闪屏**：长按控制器 `viewDidLoad` 提前调用新版面板，独立更高层级 UIWindow 盖住原生转场；面板关闭后销毁窗口；原生入口兜底保留。部分未公开操作依然需要原生回退。
4. **图片合集缩略图**：除 `AWEFeedViewCell` 外，也在 `AWEFeedTableViewCell` 的 `setModel:`、布局及复用中配置和清理，避免未挂载或复用残留；切换动画仍用原来的图集实现。
5. **自动下一条**：除 `AWEFeedContainerViewController` 外，尝试在 `AWEFeedTableViewController` 绑定播放器和查找可见列表；接近结尾的容差改为 0.85s，延后检查后仅在仍为同一条时补翻页；若 40.8.0 使用不同内部进度/滚动容器，则需要真机运行时日志继续适配。
6. **解析/保存视频**：原 `保存视频` 只检查 `h264URL`，很多视频不会提供该字段；改为在 `playURL`、`h264URL`、`playLowBitURL` 之间寻找可用地址。不填解析 API 时可通过“解析下载地址”复制已加载的原视频地址，或通过保存视频直接下载；如配置了 API 则继续使用原解析 API（该第三方接口需真实可用）。
7. **位置**：进度条默认下移 **40 pt**（旧版 8pt × 5）；底栏标题默认下移 **60 pt**（旧版 6pt × 10）。已放宽原先的 24pt/18pt 上限；旧版保存的 8/6 默认值在第一次运行 1.8 时迁移到 40/60，其他自定义值尽量保留。

## 编译与验证

- 用适配的 Theos 与 iOS SDK 编译，例如 `make package SCHEME=rootless`，安装完成后**彻底退出并重新打开抖音**。
- 检查设置主页顶部显示 **「已加载插件版本 1.8」**；如果仍为旧界面，说明安装的 DEB、注入顺序或载入版本需要先排查，不应继续改视觉参数。
- 运行后诊断报告：应用缓存目录 `DYYY-40.8.0-compat.txt`，在启动约 8 秒后写出，用于检查私有类和方法是否存在。报告只记录类名、方法是否存在及界面视图类计数，不收集视频或用户内容。
- 长按、图集和自动连播依赖 40.8.0 的私有类；如果运行时报告显示缺失，需要设备端验证后替换为实际运行类。静态检查不能证明完整功能。
- 底栏标题下移 60 pt 可能使标签进入底部安全区域或被父视图裁剪。如果看不到标题，先在设置中把此值降到 20–30 pt；40 pt 进度条也可能遮挡文字。
