# AutoAnswerCall 1.18.1 — iOS 17.3 系统接听伴随诊断版

系统自动接听继续负责建立蜂窝通话；AutoAnswerCall 只观察已接通来电，尝试本机音频播放并在匹配到真正的「添加」控件时提供人工接管按钮。

## 本版新增

- `CALLUI_UI_INIT`、`CALLUI inventory`：只采集控件**类名、尺寸、父视图类型**和语义匹配数量，不采集联系人名称或号码。
- InCallService 的 `hostreport.summary` 定期附加 `ui=... decision=...`，在沙盒日志文件不可读时也可从设置页的宿主报告尝试读取实际界面状态（跨进程可见性不保证）。
- 音频发生 AVAudioSession interruption **Began** 时立刻标记中断、停止本机播放器，不再误把播放尝试当作持续播放。
- 播放状态从 `starting` 变为 `playing` 仅在播放进度 `>0.1s` 后，从而避免停止按钮依据假的成功状态显示。
- 修正设置页长期误报“活体按钮自动接听”的旧版启动说明：本模式下系统负责接听。

## 严格限制

没有确认能在 iOS 17.3 真机上替换通话界面的「添加」按钮。缺少兼容的蜂窝电话**上行音频注入**路径；`AVAudioPlayer` 只能作为本地播放诊断，不能使来电人听见 MP3。电话助手的 CallAudioService 静态证据是音频**采集**，不能证明支持向通话写入。

请保留电话助手和系统辅助功能的原有设置，用另一部手机拨入测试；如通话控件未显示，导出全量日志，查看 `CALLUI_UI_INIT`、`CALLUI inventory`、`MANUAL_HANDOFF`、`hostreport`、`AUDIO_DIAG`。备份旧包后再测试，遇到通话声音异常立即卸载本插件。

历史版本 1.15.0、1.16.0 和 1.17.2 的逻辑已在后续版本迭代，旧版主动接听扫描路径不再在 1.18.1 的系统接听模式执行。历史变更详见 `FIXES-1.17.9.md` 与 `FIXES-1.18.1.md`。

## 1.18.1 上行 PCM 验证（实验功能）
- 「上行PCM解码验证」默认关闭。启用后，已观察到响铃并系统接通的来电会触发 SpringBoard 仅解码所选音频前 2 秒，输出 16kHz/单声道/S16 的帧数和幅度统计。此模式**不会外放，不会向通话对方发送声音**，并覆盖旧的本机播放实验。
- 没有经过验证的 iOS 17.3 蜂窝音频上行接口，`AACUplinkAdapter.h` 明确失败关闭（`UNAVAILABLE` / `sentFrames=0`）。
- 查看 `FIXES-1.18.1.md` 里的测试矩阵、研究引用和远端成功判定。
