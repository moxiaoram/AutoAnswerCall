# 影流助手 2.0.19 — 同时开启视频防错位和底栏透明

## 问题及根因

在 2.0.18 中，防错位模式保持 `AWEFeedTableView` / Cell 原生尺寸，避免上下两条视频同时出现。但透明开关只能清除底栏绘制层；当视频播放表面和滚动容器只延伸到底栏上沿、父层依旧裁剪时，底栏下方只能看到黑色。

关闭防错位后，旧版代码会扩大整个 Feed 的 frame，因此能看到视频，但修改了分页视口而没有相应修改 Cell 分页约束，导致视频页面错位。

## 2.0.19 处理

1. 保持 `DYYYStableFeedLayout=YES` 时 **绝不修改 Feed 表、视频 Cell 的 `frame`、`bounds`、分页尺寸或 `contentOffset`**。
2. 仅当 `DYYYHideBottomBg=YES`、底栏确实可见且位于播放器同一个 `UIWindow`，并且当前视频画面全宽、底边紧邻底栏、剩余空白 25–145pt 时，单独延伸当前 `AWEDPlayerFeedPlayerViewController / AWEDPlayerViewController_Merge` 的 `contentView` 到屏幕底部。不会创建快照或复制视频层。
3. 解除 **活动播放器路径上确实裁剪底部** 的祖先视图裁剪，缓存并在模式关闭或播放器切换时恢复；采用弱引用避免悬挂视图引用。不会统一取消整个应用中的裁剪。
4. 禁止 `UIView -setFrame:` 旧全局 Hook 在防错位模式修改任意播放器子视图高度，避免多级高度补偿和反复布局；停止 `TTPlayerView` 在稳定透明模式把黑色底图传给外层容器。
5. 当 Feed 开始滑动、Cell 被复用或者播放器控制器消失时，撤销该播放器的底部溢出，避免下一条视频的内容透出。
6. 保留长按面板、评论毛玻璃、图标、下载与其他 2.0.18 功能，不修改 RootHide 严格链接配置。
7. 原有底栏透明诊断额外报告当前播放器是否启用底部延伸及其屏幕位置；不包含账号、视频地址或 Token。

## 限制

这是**针对当前源码明确存在的裁剪和视口冲突的修复**，经过的是源码静态回归测试，**不是 iOS 17.3 / Douyin 40.8.0 真机通过的结论**。部分页面视频渲染视图不是上述两类 controller 或原生 tabbar 容器不符合安全条件时，不进行激进的全屏改动；如还有黑条，请通过“底栏透明诊断”导出 `Documents/AwemeVision-Footer-Diagnostic.txt` 进一步确定视图层级。

建议同时打开 **视频界面防错位（推荐）** 和 **隐藏底栏背景**，退出抖音进程后重开，先测试推荐页，连续切换多条视频，再测试搜索/详情页面。仅在 Tabbar 实际可见的首页运行本次底栏延伸逻辑。
